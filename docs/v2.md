# Experimental v2 no-mount profile

Phase 2 adds an opt-in `devbox-v2` Colima profile without host filesystem
mounts. It is separate from the legacy `devbox` profile: it has its own
ownership marker, state, lock, and runtime data, and it never updates the host
SSH configuration or Docker CLI configuration.

## Use

Create a mode-0600 `.env` with the required Git identity settings, then run:

```sh
devbox v2 start
devbox v2 connect
devbox v2 exec uname -a
devbox v2 stop
```

`devbox v2 provision` forces provisioning, while `start` is digest-idempotent.
`devbox v2 destroy` requires typing `devbox-v2` and removes only v2 runtime
data. There is intentionally no v2 IDE alias, container command, credential
management command, guest identity, or workspace in this phase.

## Provisioning bundle

The host computes a SHA-256 content digest from a sorted list of files in the
current checkout's `provision/` tree. If the guest's v2 digest is stale, the
tree is streamed over Colima SSH, extracted in a guest-local temporary
directory, and atomically installed at
`~/.local/share/devbox-v2/bundles/<digest>`. The system, tools, and verify
scripts use that installed tree through `DEVBOX_PROVISION_ROOT`; `/provision`
is not present or required.

The allowlisted guest environment is streamed separately into
`~/.config/devbox-v2/env` with mode 0600. This does not establish a dedicated
v2 user, workspace, or authentication lifecycle; those are deliberately left
to Phases 3 and 4.

## Network boundary

This feature only removes host filesystem mounts. It is not a strict network
isolation claim and does not depend on the separate `devbox isolation-poc`
experiment. Phase 1 established that stock Colima 0.10.3 retains a Lima
`user-v2` network; that unresolved limitation remains in scope for the POC,
not this profile.
