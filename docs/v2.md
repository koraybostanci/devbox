# Experimental v2 no-mount profile

Phase 2 introduced an opt-in `devbox-v2` Colima profile without host filesystem
mounts. Phase 3 adds its guest identity and workspace. It is separate from the
legacy `devbox` profile: it has its own ownership marker, state, and runtime
data, but intentionally shares the legacy lifecycle lock to serialize lifecycle
and managed SSH-configuration changes. It never updates the host Docker CLI
configuration or the legacy `devbox` SSH configuration.

## Use

Create a mode-0600 `.env` with the required Git identity settings, then run:

```sh
devbox v2 start
devbox v2 connect
devbox v2 exec uname -a
devbox v2 stop
```

`devbox v2 provision` forces provisioning, while `start` is digest-idempotent.
`devbox v2 destroy` requires typing `devbox-v2` and removes only v2 runtime
data. Daily v2 commands run as the unprivileged `devbox` user, whose home is
`/home/devbox` and whose writable workspace is `/home/devbox/workspace`.
There are no v2 `~/projects` or `~/data` links or mounts.

After `devbox v2 start`, direct SSH and IDE clients can use the separate
`devbox-v2` OpenSSH alias. It uses Colima's dedicated host key and authenticates
as guest `devbox`; the legacy `devbox` alias remains unchanged. The generated
Colima account is intentionally host-only administration transport for bundle
deployment and root provisioning. Credential/configuration lifecycle and
services remain future phases.

## Provisioning bundle

The host computes a SHA-256 content digest from a sorted list of files in the
current checkout's `provision/` tree. If the guest's v2 digest is stale, the
tree is streamed over Colima SSH, extracted in a root-owned guest-local
temporary directory, and atomically installed below
`/var/lib/devbox-v2`. The system, tools, and verify scripts use a root-owned,
read-only provisioning input through `DEVBOX_PROVISION_ROOT`; `/provision` is
not present or required.

Phase 4a makes the guest-local configuration authoritative under
`/home/devbox/.config/devbox-v2/`, owned by `devbox` (directory mode 0700,
files mode 0600):

- `config` - non-secret defaults (Git identity, PostgreSQL user/database/port).
  It is seeded once from the host and then maintained in the guest.
- `secrets` - service secrets generated inside the guest only. The PostgreSQL
  password is generated locally and is never read from or written to the host.

Authentication lifecycle is deliberately left to Phase 4b (optional provider
authentication).

## Network boundary

This feature only removes host filesystem mounts. It is not a strict network
isolation claim and does not depend on the separate `devbox isolation-poc`
experiment. Phase 1 established that stock Colima 0.10.3 retains a Lima
`user-v2` network; that unresolved limitation remains in scope for the POC,
not this profile.
